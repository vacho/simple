# 0002. SQLite through better-sqlite3 and Drizzle ORM

- Status: Accepted
- Date: 2026-10-22
- Change: bootstrap-app-foundation (`openspec/changes/archive/2026-10-29-bootstrap-app-foundation/design.md`, decision D3)

## Context

One household, a low write rate, self-hosted on modest hardware. The data must be easy to back up and inspect, and the schema must evolve through versioned migrations.

## Decision

Store everything in a single SQLite database (WAL mode), accessed through `better-sqlite3` and Drizzle ORM. Migrations are SQL files generated by `drizzle-kit`, committed to git and applied at startup, after a pre-migration backup when the database already has a schema. Transactions are synchronous: async work happens before them.

## Consequences

- No database server to run; a backup is a single file.
- One writer at a time, which WAL and `busy_timeout` cover at household scale.
- Code cannot `await` inside a transaction; use cases do their async work first (see 0008).
- Moving to another database would mean rewriting the data layer and the transaction model.

## Alternatives considered

- Prisma: heavier engine, less control over the generated SQL.
- Kysely: a good query builder, but more work for schema-first migrations.
- `node:sqlite`: backup support and ecosystem integration less settled.
