# ADR Review

## ADRs in force reviewed

- 0001 (SvelteKit 3 with the Node adapter): followed; new pages use form actions and `load`.
- 0002 (SQLite, synchronous transactions): followed; changing one's own password uses two transactions around the async hash, like sign-in (D3), and the last-administrator check relies on transactions being serialized.
- 0003 (own session authentication): extended, not changed: deactivated accounts are refused like a wrong password, so sign-in still reveals nothing (D2).
- 0004 (deny-by-default policy layer): followed; every new action gets a matrix row (D5), and the temporary password gate lives in `can()`.
- 0005 (money) and 0006 (translations): 0005 doesn't apply; 0006 is followed for every new text, with base classes as translated fixed values and names as untranslated user data (D7).
- 0007 (UUIDv7 and idempotent creates): followed for member types and members (D4); user accounts keep integer IDs, which 0007 allows for server-only tables.
- 0008 (modular monolith by feature): followed; a new `household` feature, account management split between `users` and `auth` without forwarding-only functions, and the members list reading `users` through `queries.ts` (D1, D3).
- 0021 (dates and time zones): followed; new timestamps are stored in UTC.
- 0023 (the app in `app/`): followed; every path in the design is relative to `app/`.
- 0010, 0015, 0017, 0018, 0020, 0024, 0025 (process): carried out by the `change-flow` skill; they don't affect the design. This change is a minor release (0018).

The design departs from none of them.
