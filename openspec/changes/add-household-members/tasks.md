# Tasks

Tests: each task writes the behavior tests its verification requires. Strict traceability, meaning every spec scenario has a test whose name quotes it in the `Name: detail` form, is checked when the change is closed (task 8.2). Specs may change while implementing and testing: update the spec first (update workflow, skill `openspec-update-change`), then the tests. When a task cites a requirement, it covers all of that requirement's scenarios.

Paths are relative to `app/`, and commands run there (ADR 0023). E2e tests use the existing helpers in `tests/e2e/app.ts` (production build, one database per test), extended with helpers to create members and accounts.
